# Synthetic Glacier — Step-by-Step Tutorial

Simple numerical experiments using a synthetic bedrock topography. Useful for testing and benchmarking IGM without real-world data. Each step builds on the previous one, introducing new features.

The synthetic bedrock is a U-shaped valley (10 km x 20 km, 100 m resolution) generated by `user/code/inputs/synthetic.py`.

**Tip:** Prefix any command with `TF_CPP_MIN_LOG_LEVEL=3` to suppress verbose TensorFlow messages.

## Steps

### Step 1: Basic simulation (`params_step1.yaml`)

A simple advance-retreat simulation using the built-in `smb_simple` module with time-varying ELA. Runs from 2000 to 2500.

```bash
igm_run +experiment=params_step1
```

Results are saved in a timestamped subfolder under `outputs/`. The main output file is `output.nc`, which can be visualized with `ncview`, the NetCDF viewer extension in VS Code, or any NetCDF-compatible tool.

### Step 2: With particle tracking (`params_step2.yaml`)

Same as Step 1, but adds particle tracking to visualize ice flow paths.

```bash
igm_run +experiment=params_step2
```

Results are saved in a timestamped subfolder under `outputs/`. Open `output.nc` with `ncview` or any NetCDF viewer.

### Step 3: Optuna parameter optimization (`params_step3.yaml`)

Uses the Optuna sweeper for multi-objective optimization: finds optimal sliding coefficient (`init_slidingco`) and ELA that match target ice volume and surface speed. The custom `eval_objective` module computes cost functions stored in `state.score`, which the Optuna sweeper reads to guide the search.

```bash
# Single run (no optimization):
igm_run +experiment=params_step3

# With Optuna optimization (200 trials, 3 in parallel):
igm_run -m +experiment=params_step3 hydra/sweeper=igm_optuna
```

Optimization results are stored in `multiruns/`. Each trial output is in a separate subfolder. The Optuna study is persisted in an SQLite database (`optuna.db`). You can visualize the optimization results interactively with:

```bash
pip install optuna-dashboard
optuna-dashboard sqlite:///optuna.db
```

This opens a web dashboard where you can explore trial histories, parameter importances, and Pareto fronts.

## Custom Modules

| Module | Description |
|--------|-------------|
| `synthetic` (input) | Generates a U-shaped valley bedrock topography (Steps 1-3) |
| `eval_objective` | Computes cost functions (volume, speed, thickness) for Optuna optimization (Step 3) |

## Optuna Configuration (`optuna_params.yaml`)

The optimization is configured in `optuna_params.yaml`:
- **Objectives**: minimizes `cost_volume` (distance to target 18 km³) and `cost_speed` (distance to target 200 m/y)
- **Control parameters**: `init_slidingco` (log-scale, 0.01-1.0) and ELA (2500-3200 m)
- **Sampler**: NSGAIIISampler (genetic algorithm, suited for multi-objective)
- **Parallelism**: 3 jobs with GPU memory growth enabled
